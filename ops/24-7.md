# ARA 24/7 — wat er gekoppeld moet worden

De wereld draait. De agents hebben rollen, playbooks, een takenbord en een
watchdog. Wat ontbreekt is de aansluiting op de werkelijkheid: **24 van de 25
databronnen staan op `configured: false`**, en zes schakelaars staan uit —
`ARA_RHYTHM`, `ARA_DISPATCH`, `ARA_QA_SAMPLE`, `ARA_IMPROVE`, `ARA_AUTO_UPDATE`
en `ARA_INBOX`. Alle zes staan uit omdat ze uit zichzelf tokens uitgeven of werk
draaien dat niet vanaf deze Mac gestart is; dat hoort een bewuste keuze te zijn.

Dit is de volgorde waarin dat werkt, van gratis naar duur. Elke stap is af te
vinken en elke stap levert iets op zonder dat de volgende af is.

---

## Fase 0 — Aanzetten wat er al is (één avond, geen data nodig)

### 0.1 Telefoon-toegang
```bash
./scripts/expose.sh tailnet
```
Geeft een `https://…`-adres. Tailscale-app op de iPhone, inloggen met hetzelfde
account, adres openen, deelknop → "Zet op beginscherm".

Werkt overal (4G, buitenland). Tailscale is een privénetwerk tussen je eigen
apparaten, geen open poort. **De artifact in de Claude-app is de demo**, niet je
wereld: een pagina op claude.ai mag van de browser geen verbinding naar buiten
maken, dus die kan je Mac niet bereiken. Je echte ARA staat op het adres hierboven. **Niet** `expose.sh public` gebruiken: dat zet je
hele sessiegeschiedenis achter één token in een URL.

### 0.2 Telegram — anders merk je een escalatie pas als je kijkt
Praat met `@BotFather` in Telegram → `/newbot` → token. Stuur je bot één bericht
en haal je chat-id op:
```bash
curl -s "https://api.telegram.org/bot<TOKEN>/getUpdates" | grep -o '"id":[0-9-]*' | head -1
```
Dan:
```bash
export ARA_TELEGRAM_BOT_TOKEN="…"
export ARA_TELEGRAM_CHAT_ID="…"
./scripts/install.sh
```
Vanaf nu: needsHuman, storingen, het maandagse handelsrapport en het dagelijkse
levensteken komen binnen. **Uitblijvende post is zelf het alarm** — geen bericht
betekent dat de Mac of de watchdog eruit ligt.

### 0.3 Het werk aan — ritme én uitvoering, in één commando
```bash
ARA_RHYTHM=1 ARA_RHYTHM_VENTURES=blex,traject \
ARA_DISPATCH=1 ARA_DISPATCH_MAX=2 \
./scripts/install.sh
```
**Deze twee schakelaars horen bij elkaar en moeten samen aan.** `ARA_RHYTHM` zet
terugkerend werk op het bord; `ARA_DISPATCH` haalt het er weer af door de rol te
wekken die het op zijn naam heeft. Zet je alleen het ritme aan, dan loopt het bord
vol en komt er niemand — precies wat je eigen manager terugmeldde. Zet je alleen
dispatch aan, dan gebeurt er niets, want er staat niets.

Wat dit kost, eerlijk: het ritme plaatst taken en dispatch start **hoogstens twee
sessies per tick** (`ARA_DISPATCH_MAX`, watchdog draait elke 5 min). Daarom twee
takken en niet acht. Het dagbudget uit `org.json` gaat vóór allebei, en na twee
mislukte pogingen op dezelfde taken stopt het spawnen vanzelf met een melding.

Kijk een week hoe het loopt: `pnpm retro` laat zien wie waarop vastliep, de
tokentabel wat het kostte. Pas daarna takken erbij.

### 0.4 De Mac mag niet in slaap vallen
Systeeminstellingen → Batterij/Energie → schermbeveiliging mag, slaapstand niet.
Een dichtgeklapte iMac is een zwarte pagina op je telefoon.

### 0.5 De keten één keer echt testen
```bash
pnpm verify:agents
```
Kost één korte haiku-sessie. Draait de spawn-keten, de kantoorchat en zeven
harde rolgrenzen. Draai dit na installatie en na elke Claude Code-update.

## Fase 1 — Wat agents nú al kunnen, zonder één databron

Deze werken op wat er al in huis is en leveren meteen iets op:

| rol | wat hij doet | wat hij nodig heeft |
|---|---|---|
| `ara-security-auditor` | secrets in de repo, kwetsbare dependencies | niets — git + npm |
| `ara-dependency-warden` | bumps op een branch | niets |
| `ara-doc-writer` | docs die uit de pas lopen met de code | niets |
| `ara-qa-verifier` | controleert andermans werk | niets |
| `ara-backup-verifier` | wekelijkse restore-proef van de db | een backup — die maakt de watchdog nu zelf, dagelijks (`ARA_BACKUP=0` zet dat uit) |
| `ara-org-auditor` | maandelijkse controle op de org zelf | niets |
| `ara-reporter` | kantoorcijfers die niet uit een bronbestand komen (`POST /office/:project/station`) | een `path` in projects.json; gevulde bronnen vullen de bureaus al zelf |

Sinds elke `duty` een eigenaar heeft (`who` in het playbook) staan deze rollen ook
echt in het ritme: een test weigert een playbook waarin een rol die géén databron
nodig heeft zonder terugkerend werk zit. Zonder dat bleef het bord leeg om een
reden die niets met data te maken had.

Het ritme zet elke duty bij zijn eigenaar (`who`) op het bord, en de **ops-duties**
(backupcontrole, organisatie-audit, beveiligingsaudit — in `org.json` onder `ops.duties`)
lopen daarin mee als eigen groep. Dispatch wekt dan de rol die erop staat.

**Actie:** zorg dat elk project een `path` heeft in je `projects.json` (`localPath`
werkt ook — de collector leest allebei). Zonder dat blijft de Gemeten-tab leeg.
De bureaus zelf vullen zich uit de bronbestanden van fase 2 (`stationsFromSources`,
0 tokens); `ara-reporter` begint waar een bron nog `ontbreekt` of `leeg` is.

## Fase 1b — Pas als er een week werk op het bord staat

Deze twee kijken naar wat er al gebeurd is. Ze aanzetten op een leeg bord levert
niets op, en dat is geen storing maar het ontwerp: onder de drempels zwijgt de
terugblik liever dan dat hij een patroon verzint.

### 1b.1 Agents die elkaars werk nakijken
```bash
ARA_QA_SAMPLE=20 ./scripts/install.sh
```
Van elke afgeronde taak wordt dan ~20% als `CONTROLE:`-taak bij `ara-qa-verifier`
neergelegd. Dit staat op de **collector**, niet op de watchdog. Begin laag: elke
controle is een extra sessie, dus 100 betekent dat je organisatie niets anders meer
doet dan zichzelf nakijken. `0` is uit en is de standaard.

Een controletaak wordt zelf nooit gecontroleerd, en escalaties evenmin — die wachten
op jou. Dat zit in de code (`shouldVerify()`), niet in een prompt.

### 1b.2 De verbeterronde
```bash
ARA_IMPROVE=1 ARA_IMPROVE_DAYS=7 ./scripts/install.sh
```
Eén keer per dag leest `ara-org-auditor` de gemeten terugblik en schrijft per
bevinding hoogstens één voorstel op het bord, met de taak-ids waar het op rust. Hij
wijzigt zelf niets — niet aan code, niet aan `org.json`, niet aan het ritme.

**Hij draait alleen als er iets te wijzen valt.** Te weinig taken in het venster, of
geen patronen gevonden, en er start geen sessie. Lees het eerst zelf een paar keer
met `pnpm retro` voordat je hier tokens aan uitgeeft — dat kost er nul.

## Fase 2 — Databronnen: elk bestand is een koppeling

Elke bron uit de playbooks is één bestand onder `data/sources/<tak>/` — 24 in
totaal, kolommen in `ops/sources/README.md`. Geen sleutel, geen API: een export
of het statusbestand dat je bot zelf schrijft. Staat het bestand er mét regels,
dan is de bron aangesloten en verdwijnt hij uit de actielijst; een lege kop
telt niet.

```bash
pnpm sources:init                      # maakt alle ontbrekende bestanden aan (alleen de kop)
curl -s localhost:4747/sources | jq '.ventures[] | {id, open: [.sources[] | select(.state != "gevuld") | .file]}'
```

Wat erin staat en op jou wacht — verlopen APK, positie zonder stop, onbetaalde
factuur — komt in de actielijst; het blokkerende deel ook op je telefoon (één keer
per feit per dag, `ARA_SOURCES_ALERT=0` zet dat uit).

Volgorde van opbrengst:

1. **Blex** — `vehicles.csv`, `drivers.csv` (compliance rekent meteen: `GET /fleet`),
   dan `garage.csv`, `kosten.csv`, `trailers.csv`.
2. **Traject** — `ritten.csv`, `facturen.csv`. Lezen is genoeg; migraties en
   externe transport-API's blijven een automatische ESCALATE.
3. **Elevate / Uprising / Vovara** — `opdrachten.csv` + `sites.csv`,
   `boekingen.csv` + `aanvragen.csv`, `releases.csv` + `releaseplanning.csv`.
4. **Handel, crypto, aandelen** — zie fase 3; de bestanden staan al in de tabel.

## Fase 3 — Handel, apart, omdat het geld raakt

De keten is gebouwd en getest, maar staat bewust dicht:

1. **Limieten** — `data/trading-limits.json`. Zonder dat bestand valt alles terug
   op `DEFAULT_LIMITS`: lege witte lijst, `accountValue: 0`, **er komt niets
   doorheen**. Dat is geen storing, dat is het ontwerp.
2. **Modus** — staat op `paper`. Omhoog vereist
   `ARA_TRADING_UNLOCK=yes-i-accept-the-risk` in de omgeving van de collector.
   Dat kan niet via de API, met opzet.
3. **Bronnen** — posities, P&L en stops moeten ergens vandaan komen. Publieke,
   sleutelloze koersendpoints voor prijzen; je eigen export voor posities.
4. **Nooit een sleutel met handelsrechten in ARA.** In `live` komt er een
   *handoff* klaar te staan voor een adapter die jij zelf draait.

**Aanbevolen volgorde:** limieten invullen → een maand papier draaien →
`pnpm trade:review` lezen → pas dan nadenken over `approval`.

De drempels staan al in de code (`REVIEW_THRESHOLDS`): minstens 30 afgeronde
trades over minstens 20 actieve dagen. Die zijn er om je tegen jezelf te
beschermen, niet om afgevinkt te worden.

## Doorlopend

- **Dagbudget** staat op 2.000.000 tokens in `org.json`. Ritme, dispatch en de
  verbeterronde kijken daar allemaal eerst naar: is het op, dan komt er geen werk
  bij en start er niets meer.
  Sinds kort telt dat budget **alleen sessies die ARA zelf startte**. Jouw eigen
  Claude Code-werk op dezelfde Mac staat in dezelfde tabel maar telt niet mee —
  daarvoor zette een dag zelf ontwikkelen je agents stil terwijl die niets hadden
  uitgegeven (gemeten: 15,9 miljoen tokens tegen een budget van 2 miljoen, waarvan
  14,1 miljoen cache-creatie uit één ontwikkelsessie).
- **Backup** — de watchdog maakt elke dag een kopie van de database in `~/Backups/ara`
  (`ARA_BACKUP_DIR`), 14 bewaard, 0 tokens. De eerste proefdraai van de backup-verifier
  kwam terug met ESCALATE: de map bestond niet, want niemand had het commando ooit
  gedraaid. Een controle zonder iets te controleren is de reden dat dit nu vanzelf gaat.
- **`pnpm retro [dagen]`** leest het bord terug: wie liep waarop vast, wat staat er
  stil, wat blijft terugkomen. Kost nul tokens, dus lees 'm gerust wekelijks.
- **`pnpm ara:update`** haalt nieuw werk op, bouwt en herstart. Eén regel.
- **`ARA_AUTO_UPDATE=1`** laat de watchdog dat zelf doen. Zet dit pas aan als er
  een week niets brekends gepusht is.
- **`ARA_INBOX=1`** laat een `.md` in `ops/inbox/` een bordtaak worden — werk
  aanleveren vanaf een andere machine, via git.

## Wat expliciet níét gekoppeld wordt

- Geen broker- of exchange-sleutel met handelsrechten. Nooit.
- Geen publicatierechten waar de tak dat niet toestaat: Elevate is klantwerk en
  gaat nergens naar buiten; bij Vovara mag de site live maar een release
  uitbrengen niet; bij Uprising mag productie behalve de boekingsflow.
- Geen schrijftoegang tot productiedatabases. Migraties escaleren altijd.
